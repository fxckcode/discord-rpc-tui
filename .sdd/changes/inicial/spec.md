# Spec: Discord Rich Presence TUI

## Requirements

### Functional
- [ ] REQ-F1: TUI must display connection status (connected/disconnected/connecting/discord-offline)
- [ ] REQ-F2: TUI must show current activity details (state, details, timestamps)
- [ ] REQ-F3: Must support multiple profiles with rotation at configurable interval
- [ ] REQ-F4: Must auto-reconnect when Discord restarts
- [ ] REQ-F5: Must detect if Discord is running (check /tmp/discord-ipc-0)
- [ ] REQ-F6: Config file must be at ~/.config/discord-rpc-tui/config.json
- [ ] REQ-F7: Config must support: clientId, transport, profiles[], rotationInterval, startOnBoot
- [ ] REQ-F8: Each profile must support: state, details, startTimestamp, endTimestamp, largeImageKey, largeImageText, smallImageKey, smallImageText, buttons[], type
- [ ] REQ-F9: Keybindings: q=quit, Space=toggle pause, n=next activity, r=reload config
- [ ] REQ-F10: Log panel showing RPC events (connected, activity set, error, reconnecting)
- [ ] REQ-F11: systemd service autogenerated at ~/.config/systemd/user/discord-rpc-tui.service

### Non-Functional
- [ ] REQ-NF1: Written in TypeScript, strict mode
- [ ] REQ-NF2: Zero external config editing required after first setup
- [ ] REQ-NF3: Must not crash on Discord disconnect — graceful degradation
- [ ] REQ-NF4: Must not leak file handles or interval timers on exit

## Scenarios

### Happy Path: Start
1. User runs `rpc-tui` (or systemd starts it)
2. App reads config from ~/.config/discord-rpc-tui/config.json
3. TUI renders with StatusBar showing "Connecting..."
4. RPC connects to Discord IPC
5. StatusBar shows "Connected"
6. First profile activity is set
7. Log shows "Connected" + "Activity set: [profile name]"

### Happy Path: Activity Rotation
1. Timer ticks (every N seconds from rotationInterval)
2. Next profile in queue is activated
3. Log shows "Rotating to: [profile name]"
4. ActivityEditor updates to show new activity

### Error: Discord not running
1. DiscordDetector polls /tmp/discord-ipc-0 every 5 seconds
2. If not found, StatusBar shows "Discord Offline"
3. RPC Manager does not attempt connection
4. When socket appears, auto-connect

### Error: Discord restarts
1. RPC socket disconnects
2. RPC Manager detects close event
3. StatusBar shows "Reconnecting..."
4. Retry loop with backoff (1s, 2s, 4s, 8s, max 30s)
5. On reconnect, restore last activity

## API Contract
### Config Schema
```typescript
interface Config {
  clientId: string;
  transport: 'ipc' | 'websocket';
  profiles: Profile[];
  rotationInterval: number; // seconds, 0 = no rotation
}

interface Profile {
  name: string;
  activity: {
    state?: string;
    details?: string;
    startTimestamp?: boolean | number; // true = now, number = epoch ms
    endTimestamp?: number;
    type?: ActivityType;
    largeImageKey?: string;
    largeImageText?: string;
    smallImageKey?: string;
    smallImageText?: string;
    buttons?: { label: string; url: string }[];
  };
}
```

### RPC Manager API
```typescript
class RPCManager {
  on(event: 'connected' | 'disconnected' | 'activity-set' | 'error', handler): void;
  async connect(clientId: string): Promise<void>;
  async setActivity(activity: Activity): Promise<void>;
  async destroy(): Promise<void>;
}
```
